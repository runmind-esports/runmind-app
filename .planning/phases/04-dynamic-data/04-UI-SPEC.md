# Phase 4 — UI Design Contract

> Visual and interaction contract for the Dynamic Data phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (components.json present, style: default, baseColor: neutral) |
| Preset | default -- cssVariables: false |
| Component library | Radix UI (existing: avatar, button, scroll-area, textarea, theme-toggle) |
| Icon library | Lucide React ^0.312.0 |
| Font (body) | Manrope (400, 700) via Google Fonts import |
| Font (display) | Poppins (400, 700) via Google Fonts import |
| Animation library | CSS keyframes + Intersection Observer API (no new dependencies) |

**Phase 4 scope:** This phase delivers 1 new section component (NumbersSection), 1 new UI primitive (AnimatedCounter), 1 new custom hook (useCountUp), and 1 new service function (fetchLandingMetrics). It also updates the translation dictionary to replace all `[Phase 4]` placeholders with final copy. The section fetches data from `runmidApiClient` and falls back to hardcoded values if the API is unavailable. Counter animations use pure JavaScript `requestAnimationFrame` -- no Motion dependency needed.

**Why no Motion library:** Phase 3 established CSS-first animations. Counter animations require JS-driven number interpolation (not CSS-animatable), but `requestAnimationFrame` handles this natively with zero bundle cost. This avoids 30-50KB bundle bloat on Brazilian mobile 4G connections.

## Component Visual Specs

### AnimatedCounter

- Wrapper: `<div>` with `text-center`
- Number display: `text-[32px] md:text-[40px] font-bold font-display text-accent leading-[1.1]`
- Suffix (unit): displayed inline after number, same size and color (`text-accent`)
- Animation: eases from 0 to target value over 2000ms using `requestAnimationFrame`
- Easing function: `easeOutCubic` -- `t => 1 - Math.pow(1 - t, 3)` -- fast start, smooth deceleration
- Trigger: animation starts when `enabled` prop becomes `true` (controlled by `useInView` in parent)
- Pre-animation state: displays "0" (not blank, not hidden) -- no layout shift
- Post-animation state: displays final formatted value, animation complete
- Respects `prefers-reduced-motion: reduce` -- if enabled, skip animation and display final value immediately

### NumberCard (inline in NumbersSection, not a separate component file)

- Background: `bg-background-secondary rounded-xl`
- Border: `border border-border`
- Top accent: `border-t-2 border-accent` (thin accent bar at top of card)
- Padding: `p-6 md:p-8` (24px mobile, 32px desktop)
- Layout: `text-center`
- Number + suffix: AnimatedCounter component
- Label: `text-base font-bold font-display mt-2`
- Sublabel: `text-[13px] text-foreground-muted mt-1`
- Hover: none (number cards are not interactive)

## Interaction Contract

### Counter Animation (PERF-02)

| Element | Trigger | Animation | Duration | Delay |
|---------|---------|-----------|----------|-------|
| NumbersSection title | Scroll into view | Fade up (via ScrollReveal) | 700ms | 0ms |
| NumbersSection subtitle | Scroll into view | Fade up (via ScrollReveal) | 700ms | 100ms |
| Number card 1 (Volume) | Scroll into view | Fade up + counter starts | 700ms fade / 2000ms counter | 0ms |
| Number card 2 (Pace) | Scroll into view | Fade up + counter starts | 700ms fade / 2000ms counter | 100ms |
| Number card 3 (Engagement) | Scroll into view | Fade up + counter starts | 700ms fade / 2000ms counter | 200ms |

**Counter animation details:**
- Counter animates from 0 to target value
- Volume (125000): counts through integers, formatted with locale separator at each frame
- Pace (5.4): counts through decimals, formatted as M:SS at each frame
- Engagement (94): counts through integers with % suffix
- All counters use `easeOutCubic` easing
- Counter starts when the card scrolls into view (same IntersectionObserver trigger as ScrollReveal)
- If `prefers-reduced-motion: reduce`, display final value immediately with no counter animation

**Intersection Observer config (reuse existing):**
- `threshold: 0.15`
- `rootMargin: "0px 0px -60px 0px"`
- `once: true`

### Data Fetching

| Event | Behavior |
|-------|----------|
| Component mount | Render immediately with fallback values. Fire `fetchLandingMetrics()` in parallel. |
| API success | Replace fallback values with API values. If counter animation has not started yet, use API values as target. If counter has already completed, snap to API values without re-animating. |
| API failure | Keep fallback values. Log `console.warn("Landing metrics API unavailable, using fallback values")`. No user-visible error. |
| API timeout | 5000ms timeout. Treat as failure (use fallback). |

**Implementation pattern:** `useEffect` fires fetch on mount. State holds `{ volume, pace, engagement }` initialized to fallback values. Fetch result updates state. Counter animation reads from state.

### Navigation

No new navigation interactions. Existing Phase 2/3 navigation continues unchanged.

### Hover States

No new hover states in Phase 4. Number cards are non-interactive display elements.

## API Contract

### Endpoint: `GET /metrics/landing`

**Client:** `runmidApiClient` (uses `NEXT_PUBLIC_RUNMID_API_URL`)

**Authentication:** None required (public endpoint for landing page)

**Expected Response:**
```typescript
interface LandingMetrics {
  volume: number    // total kilometers (e.g., 125000)
  pace: number      // average pace in decimal minutes (e.g., 5.4 = 5:24 min/km)
  engagement: number // engagement percentage (e.g., 94)
}
```

**Error handling:**
- Network error -> return `null`
- Non-200 status -> return `null`
- Timeout (5000ms) -> return `null`
- Malformed response -> return `null`

**Fallback values (hardcoded in component):**
```typescript
const FALLBACK_METRICS: LandingMetrics = {
  volume: 125000,
  pace: 5.4,
  engagement: 94,
}
```

**Note from STATE.md:** API endpoint `/metrics/landing` is not confirmed to exist on backend. Phase 4 implementation must work entirely with fallback values until backend confirms the endpoint. The fetch attempt should fail silently.

## Accessibility

- NumbersSection heading uses `<h2>` continuing semantic order
- AnimatedCounter uses `aria-live="polite"` so screen readers announce the final value when animation completes
- AnimatedCounter includes `aria-label` with the full metric description (e.g., "125,000 quilometros registrados")
- Number cards are not interactive -- no tab stops, no focus states needed
- `prefers-reduced-motion: reduce` disables counter animation (final value displays immediately)
- All number values are rendered as text content (not images or canvas), fully accessible to screen readers
- Suffix units are part of the same text flow, not decorative
