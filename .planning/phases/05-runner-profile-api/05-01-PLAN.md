<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> POST /api/v1/training/profile | Untrusted JSON body with profile fields |
| handler -> database | Profile data persisted via parameterized queries |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Spoofing | SaveProfile handler | mitigate | User ID comes from JWT via `c.MustGet("user").(*auth.User)`, not from request body (existing pattern) |
| T-05-02 | Tampering | trainingPreference field | mitigate | Explicit validation via `ValidateTrainingPreference()` rejects values outside the enum set |
| T-05-03 | Tampering | JSONB fields (otherActivities) | accept | json.RawMessage handled by Go stdlib JSON parser; PostgreSQL JSONB is injection-safe via parameterized queries ($N placeholders) |
| T-05-04 | Info Disclosure | GetProfile | mitigate | Profile fetched by authenticated user.ID from JWT, not URL param -- users can only read own profile (existing IDOR protection) |
| T-05-05 | Elevation | UPSERT on user_id | mitigate | ON CONFLICT (user_id) uses the authenticated user.ID, preventing profile overwrites for other users |
</threat_model>
