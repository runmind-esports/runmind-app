## Spacing Scale

Multiples of 4 — follows project convention (Tailwind default scale):

| Token | Value | Usage in this phase |
|-------|-------|--------------------|
| xs | 4px (`p-1`, `gap-1`) | Icon-to-text inline gap, savings badge inner padding |
| sm | 8px (`p-2`, `gap-2`) | Segmented control item padding, feature row icon gap |
| md | 16px (`p-4`, `gap-4`, `space-y-4`) | Card internal padding (mobile), section content spacing |
| lg | 24px (`p-5`/`p-6`, `space-y-6`) | Card internal padding (desktop), spacing between Free card and Pro card, and between Pro card and active-plan banner |
| xl | 32px (`p-8`) | Modal padding (reuses existing settings success modal — out of scope to touch) |
| 2xl | 48px | Not used in this phase |
| 3xl | 64px | Not used in this phase |

Exceptions:
- **Segmented control internal track**: `p-1` (4px) wraps three buttons at `py-2.5 px-3` (~10px / 12px) — required to hit the 36px minimum touch target on mobile while keeping visual compactness within the Pro card header.
- **Savings badge**: `px-2 py-0.5` (8px / 2px) — sub-4 vertical is acceptable for pill badges because text caps determine effective height (~18px total). Matches existing `'Recomendado'` badge convention at `PlansSection.tsx:241`.

## Typography

Project uses 3 font families (Manrope sans, Poppins display, Inter body) — for this phase, sizes are constrained to 4 roles and 2 weights:

| Role | Size | Weight | Line Height | Font family | Tailwind class |
|------|------|--------|-------------|-------------|----------------|
| Caption / muted label | 12px | 500 medium | 1.4 | Manrope sans | `text-xs font-medium` |
| Body / feature row | 14px | 400 regular | 1.5 | Manrope sans | `text-sm` |
| Card title (Free / Pro) | 16px | 600 semibold | 1.3 | Poppins display | `font-display font-semibold text-base` |
| Price display | 28px | 700 bold | 1.1 | Poppins display | `font-display font-bold text-[28px]` (or `text-2xl` ≈ 24px on mobile, see exception) |

Exceptions:
- Mobile (`<640px`) price display steps down to 24px (`text-2xl`) to avoid wrapping when both total and `/mês` effective price are on the same row.
- "Seu plano" active-plan banner heading reuses existing `text-xl` from current `PlansSection.tsx:74` — do NOT change (out of scope refactor).
- The segmented control button labels are 13px (`text-[13px] font-semibold`) — between caption and body. This is an exception because segmented controls visually need to read smaller than card titles but bolder than body to communicate "tab-like switchable state."

Weights used: **400 regular** (body, features) + **600/700 semibold/bold** (titles, prices, CTAs). Two weight buckets, no italic.

## Layout Specification

### Plans tab content order (top → bottom)

1. **"Seu plano" banner** — unchanged from existing implementation (`PlansSection.tsx:70-108`). Shows current tier (including Premium for legacy users, no change to identification logic).
2. **Error banner** — unchanged (`PlansSection.tsx:111-115`).
3. **Upgrade heading** — `"Escolha seu plano"` (replaces existing `"Fazer upgrade"` at `PlansSection.tsx:122`).
4. **Free card** — full width, secondary surface, no border accent. Hidden if `userTier !== 'free'`.
5. **Pro card** — full width, accent ribbon on top-left when recommended, accent border (`border-[#00F048]/30`). Contains:
   - **Header row**: Pro title + "Mais popular" ribbon
   - **FrequencySelector** (segmented control, full width)
   - **PriceDisplay** (large total + small `/mês` effective)
   - **Features list** (5-7 bullets from `pro_monthly.features`, identical across the 3 frequencies — backend should return the same list)
   - **CTA button**: "Assinar Pro" (or "Mudar para [frequência]" if already Pro)

Premium card: **NOT rendered, regardless of backend response.** Filter applied at the top of `PlansSection`: `plans.filter(p => p.tier !== 'premium')`.

### Frequency Selector geometry

```
┌─────────────────────────────────────────────┐
│  [Mensal]  [Semestral]  [Anual]             │  ← inactive: text-foreground-muted, bg-background-tertiary
└─────────────────────────────────────────────┘
              ▲ ACTIVE = bg-accent text-[#14162E] rounded-full
```

- Container: `bg-background-tertiary rounded-full p-1 flex gap-1 w-full`
- Each button: `flex-1 py-2 text-[13px] font-semibold rounded-full transition-colors`
- Active button: `bg-accent text-[#14162E]`
- Inactive button: `text-foreground-muted hover:bg-accent-dim`
- Touch target: ~36px height (8px padding × 2 + 13px text × 1.4 line-height ≈ 34px) — acceptable for fingers within a card context.
- Default selected: `'monthly'` on mount (no localStorage persistence — per-session state).
- Keyboard: arrow-left/right navigates between segments (tabIndex=0 on container, tabIndex=-1 on buttons; or radio role on each button).

### Price Display geometry

- Two-line layout, left-aligned:
  - Line 1: large total (28px Poppins bold) — e.g. `R$ 39,90` for monthly, `R$ 179,40` for semestral, `R$ 238,80` for yearly.
  - Line 2: small muted period (`text-xs text-foreground-muted`) — e.g. `cobrados mensalmente` / `cobrados a cada 6 meses` / `cobrados anualmente`.
  - Below line 2: small effective price (`text-sm font-medium text-foreground`) — e.g. `Equivale a R$ 29,90/mês` (Semestral) or `Equivale a R$ 19,90/mês` (Anual).
  - For Mensal: no equivalence line (the total IS the monthly price).
- Right-aligned (same row as price total on desktop, below on mobile): savings badge.
  - Mensal: no badge.
  - Semestral: `Economize 25%` badge (computed: `1 - (179.40 / (39.90 × 6)) = 0.2506 ≈ 25%`).
  - Anual: `Economize 50%` badge (computed: `1 - (238.80 / (39.90 × 12)) = 0.5012 ≈ 50%`).

Computation helper: keep existing `calcAnnualSavingsPercent` pattern from `PlansSection.tsx:24-28`, rename to `calcSavingsVsMonthly(monthlyAmount, planAmount, intervalMonths)` for the 3-interval case.

## Behavioral Contract (state machine)

```
userTier = 'free' →
  show: Seu plano banner (Free) + Escolha seu plano + Free card (with "Plano atual" pill) + Pro card (CTA: "Assinar Pro")
  click any frequency → updates billingInterval state, price display + CTA copy update synchronously, no network call
  click CTA → calls checkout(planId resolved from billingInterval) → redirects to Stripe

userTier = 'pro', userInterval = 'monthly' →
  show: Seu plano banner (Pro Mensal) + Escolha seu plano + Pro card only (Free card hidden)
  default selected frequency = 'monthly' (matches user's current interval)
  click 'monthly' → CTA shows "Plano atual" disabled
  click 'semestral' → CTA shows "Mudar para Semestral" active
  click 'anual' → CTA shows "Mudar para Anual" active
  click CTA → calls checkout(new planId) → Stripe handles upgrade with proration

userTier = 'premium' →
  show: Seu plano banner (Premium [interval]) + "Gerenciar conta" button only
  hide entirely: "Escolha seu plano" heading, Free card, Pro card
  (Premium users see no marketing — they only manage via Stripe portal)
```

`planId` resolution:
- `'monthly'` → `'pro_monthly'`
- `'semestral'` → `'pro_semestral'`
- `'yearly'` → `'pro_yearly'`

## Accessibility

- Frequency selector: render as `<div role="tablist">` containing three `<button role="tab" aria-selected="...">`. Arrow keys cycle. Active segment gets `aria-selected="true"`; others `aria-selected="false"`.
- Price changes (frequency click) live region: wrap PriceDisplay in `<div aria-live="polite">` so screen readers announce the new total when the user picks a different frequency.
- CTA button: when disabled ("Plano atual"), add `aria-disabled="true"` (not just `disabled`) and provide `title="Você já está nesse plano"`.
- Color contrast: all combinations validated above (≥ 4.5:1 for body, ≥ 3:1 for large text and graphical elements).
- Touch targets: segmented-control buttons at ~36px and CTA at ~44px (existing `py-2.5` produces ~40px + 1px ring) — both within Apple HIG (44pt) / Material (48dp) tolerance for in-card controls.
