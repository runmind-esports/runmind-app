<cross_repo_dependency>
O endpoint `POST /api/v1/whatsapp/init-token` é entregue pela Phase 5 do runmid-api (status: aguardando planejamento/execução).
Contract canonical: `~/Documents/runmid/runmid-api/.planning/phases/05-whatsapp-linking-endpoints/05-CONTEXT.md`.

Request:
- Method: POST
- Path: /api/v1/whatsapp/init-token
- Headers: Authorization: Bearer {access JWT} (já injetado pelo runmidApiClient)
- Body: {} (objeto vazio)

Response 200:
- {
-   "token": string,           // base64url, single-use, TTL 24h
-   "walink": string,          // "https://wa.me/{numero}?text=runmid-init-{token}"
-   "expiresAt": string,       // ISO 8601
-   "qrPayload"?: string       // opcional; quando presente = walink. O front pode ignorar e usar walink direto pra QR.
- }

Response 429: { "error": "...", "code": "RATE_LIMITED" } + header Retry-After (segundos)
Response 503: { "error": "...", "code": "WHATSAPP_NOT_CONFIGURED" }
Response 401: tratado transparentemente pelo runmidApiClient (refresh token flow)

Este plan codifica o cliente. O endpoint não estará disponível até runmid-api Phase 5 shippar — execute-phase deste plan pode rodar quando quiser (não depende do backend pra build/lint), mas o smoke test do Plan 02 só funciona com o backend up.
</cross_repo_dependency>
