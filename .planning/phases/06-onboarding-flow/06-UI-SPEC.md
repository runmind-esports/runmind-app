# Phase 6 — UI Design Contract

> Visual and interaction contract for the Onboarding Flow phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (components.json present, style: default, baseColor: neutral) |
| Preset | default -- cssVariables: false |
| Component library | Radix UI (existing: avatar, button, scroll-area, textarea, theme-toggle) |
| Icon library | Lucide React ^0.312.0 |
| Font (body) | Manrope (400, 700) via Google Fonts import |
| Font (display) | Poppins (400, 700) via Google Fonts import |

**Phase 6 scope:** This phase delivers a full-screen multi-step onboarding experience consisting of a welcome/name-confirmation screen followed by an 11-question runner profile form. The visual language inherits the auth page convention (light background form panels) but uses a dedicated full-screen layout without the AuthLayout split-panel. All design tokens are inherited from Phase 1.

- Welcome screen content stack: 24px (`gap-6`) between heading, name input, and CTA

## Color

Inherited from Phase 1 UI-SPEC. The onboarding flow uses **light mode only** to match the existing auth pages (login/signup), which render on a white background regardless of theme.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` | Page background, form card background |
| Secondary (30%) | `#F5F6F7` | Option button default background, input background, progress bar track |
| Accent (10%) | `#00F048` | See reserved list below |
| Foreground | `#14162E` | Headings, body text, input text |
| Foreground muted | `#6B7088` | Subtitles, helper text, progress label (matches auth page muted, not landing page `#8A8FA8`) |
| Border | `rgba(20,22,46,0.09)` | Input borders, option button borders (matches auth page convention) |
| Border focus | `#14162E` | Input focus border (matches auth page convention) |
| Destructive | `#EF4444` | Validation error text only |

**Accent reserved for (Phase 6):**
1. Progress bar filled segment
2. Selected option button border highlight
3. "Continuar" / primary navigation button background
4. Step completion checkmark icon fill
5. Name confirmation accent underline on greeting

**Light-only rationale:** The auth pages (login, signup) always render in light mode with white backgrounds and `#14162E` text. The onboarding flow is the immediate next step after signup and must maintain visual continuity. This is NOT a theme override -- the onboarding route simply does not import `ThemeProvider` toggles.

## Interaction Contract

### Step Navigation

| Trigger | Action | Behavior |
|---------|--------|----------|
| Click "Continuar" | Advance to next question | Slide-left transition (current exits left, next enters from right). 300ms ease-out. |
| Click "Voltar" | Return to previous question | Slide-right transition (current exits right, previous enters from left). 300ms ease-out. |
| Click option button | Select answer | Immediately marks option as selected. Does NOT auto-advance -- user must click "Continuar". |
| Click "Finalizar perfil" | Submit profile | Calls `onboardingApi.submitProfile()`. Shows loading state. On success, navigates to `/planilha` (Phase 7 route). |
| Click "Continuar" on welcome | Enter question flow | Validates name is not empty. Transitions to question 1. |

### Validation

| Rule | When | Visual Feedback |
|------|------|-----------------|
| Name required | Welcome step, on "Continuar" click | Red border on input + error message below |
| Selection required | Question steps, "Continuar" click with no selection | "Continuar" button stays disabled (opacity 50%) until an option is selected |
| Conditional follow-up | Q3 "Ja corre?" = Sim | Smoothly reveals km/semana options below (slide-down, 200ms). Both Sim+km range must be set to proceed. |

### Step Transition Animation

- CSS-only transitions (no external animation library, matches project convention)
- Enter from right: `transform: translateX(24px)` + `opacity: 0` -> `translateX(0)` + `opacity: 1` (300ms ease-out)
- Exit to left: `translateX(0)` + `opacity: 1` -> `translateX(-24px)` + `opacity: 0` (300ms ease-out)
- Reverse for "Voltar" navigation
- `prefers-reduced-motion: reduce` disables transitions (instant swap)

### Keyboard Navigation

- `Enter` key triggers "Continuar" / "Finalizar perfil" when an option is selected
- `Tab` + `Space/Enter` can select option buttons (buttons are focusable)
- `Escape` is not mapped (no modal to dismiss)

### Route Guard

- `/onboarding` requires authentication (check `tokenStorage.getAccessToken()`)
- If not authenticated, redirect to `/login`
- If user already has a saved profile (future check), redirect to `/chat`

## Accessibility

- Question text uses `<h2>` semantic heading for each step
- Option buttons are `<button>` elements with `role="radio"` inside a `role="radiogroup"` container
- Selected option has `aria-checked="true"`
- Progress bar uses `role="progressbar"` with `aria-valuenow`, `aria-valuemin="0"`, `aria-valuemax="10"`
- Name input has associated `<label>` with `htmlFor`
- Navigation buttons have descriptive `aria-label` when icon-only on mobile (not applicable here -- all buttons have text)
- Color contrast: `#14162E` on `#FFFFFF` = 15.4:1 (AAA). `#6B7088` on `#FFFFFF` = 4.8:1 (AA). `#14162E` on `#00F048` = 8.4:1 (AAA).
- All interactive elements meet 44px minimum touch target
- `prefers-reduced-motion` respected for step transitions
