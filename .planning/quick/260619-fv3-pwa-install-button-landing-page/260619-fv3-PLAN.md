<objective>
Make the RunMind landing page (`/`) installable as a Progressive Web App on Android and iOS without adding the `next-pwa` dependency. Manual implementation: hand-written `manifest.json`, hand-written minimal `sw.js`, PNG icons generated from existing 1024×1024 brand asset, a client component that captures `beforeinstallprompt` and renders an "Instalar app" button (with an iOS-specific instructional modal for Safari which lacks `beforeinstallprompt`), plus the required iOS meta tags and theme color in the root layout.

Purpose: Convert landing visitors into installed users so the WhatsApp coaching CTA lives on the home screen alongside native apps — without committing to App Store / Play Store distribution and without inheriting `next-pwa`'s opinionated Workbox config.

Output: Two PNG icons, one `manifest.json`, one minimal `sw.js`, one SW-registration client component, one install-button client component, and two file edits (`layout.tsx` metadata + `page.tsx` CTA mount). No new npm dependencies.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public/sw.js → user device | The service worker runs in the browser with `scope: /` — it can intercept every request on the origin. |
| public/manifest.json → install registry | The manifest declares identity (name, icons, start_url) used by the OS install registry. |
| beforeinstallprompt → install action | The prompt event captured client-side is consumed by user click. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-pwa-01 | Tampering | `public/sw.js` cached aggressively could serve stale or attacker-substituted assets to returning users | mitigate | SW is intentionally minimal — no `caches.put`, no precaching, no offline mode. Fetch handler is empty / network-only. If we later add caching this threat needs revisiting. |
| T-pwa-02 | Spoofing | An install-prompt UI that fires automatically could be confused with a native OS prompt | accept | We render a button labeled "Instalar app" — user explicitly clicks before any prompt fires. Chromium's `beforeinstallprompt` also requires `preventDefault()` + user gesture, which we honor. |
| T-pwa-03 | Information Disclosure | Service worker scope `/` means future routes (chat, settings) fall under SW control | mitigate | SW is no-op pass-through — does not read, log, or transmit request bodies. Source is 10 lines, auditable. |
| T-pwa-04 | Denial of Service | Broken SW registration could put users in an install-loop, breaking the landing | mitigate | Registration is wrapped in `.catch` that logs to `console.error` without throwing. `skipWaiting()` + `clients.claim()` ensure updates supersede old workers. To recover users we can ship an empty SW that unregisters itself — out of scope but trivially reversible. |
| T-pwa-05 | Repudiation | N/A | accept | PWA install is a client-only event; no server-side state changes occur. |
| T-pwa-SC | Tampering | Supply chain (npm/pip/cargo installs) | n/a | This plan adds NO new dependencies. `npm install` is not invoked. No package legitimacy gate required. |
</threat_model>
